# Cupertino v2 — token and style mapping

How Apple's design language maps onto the Uno Themes semantic system (shared colour roles in
`SharedColorPalette.xaml`, the generated brushes in `SharedColors.xaml`, the shared type scale in
`SharedTypography.xaml`, the `Space*` / `Radius*` / `ControlHeight*` tokens generated by `BaseTheme`, and the
semantic style keys every theme's `_Resources.xaml` aliases). Numbers come from `apple-hig-reference.md`
(Apple-published unless tagged) and `reference-cupertino-avalonia.md` (cross-check). Anything tagged
**[measure]** is not published by Apple and must be confirmed against the Figma 27 kits before the
implementing phase closes.

Idiom: **iOS / iPadOS (touch) metrics** for every default in this document. A macOS (pointer) idiom is a
follow-up (see `progress.md`, "Out of scope").

Revision 2026-09-18 (post skeptic review): container and outline roles pre-composited to opaque values;
the shared state-opacity ladder is left untouched (Apple's content dimming lives in control-level keys);
`On*Container` = label; implicit `Button` is plain, not glass; motion tokens moved into `ThemeDictionaries`
and `ReduceMotion` made construction-time; legacy opacity keys keep literal values; YAGNI cuts listed in §9.

## 1. Colour roles → `SharedColorPalette.xaml` overrides

Declared in `Uno.Cupertino/Styles/Application/ColorPalette.xaml` inside `ThemeDictionaries` (`Light`,
`Default`), exactly as Simple does. **Every shared role is opaque.** `SharedColors.xaml` multiplies each
role by the state opacities (`PrimaryHoverBrush` = `PrimaryColor` @ `HoverOpacity`, …); an alpha role would
multiply twice and every `*Container{Hover,Pressed,Selected}Brush` would vanish. Apple's alpha-based fills
are therefore pre-composited over their intended backdrop (white for Light, black for Dark) here, and kept
alpha-based only in the Cupertino-only keys of §2 for the few styles that genuinely need translucency.

`On*Container`), not Apple's tinted fills — the seeded scheme is coherent but is no longer "the Apple
look". Documented in `doc/seed-colors.md`. `DefaultPrimarySeed` stays `null` so the hand-crafted palette is
the default.

### State opacity ladder — shared values kept

`SemanticBrushUpdater` resolves the `*Opacity` tokens from the theme colour layers, so Cupertino *could*
retune them — and must not: one token carries two semantics in the existing templates (`OnSurfaceDisabledBrush`
is both a disabled foreground and a disabled fill in Simple / Material), `FocusedOpacity` 0 would blank
every `*FocusedBrush` used by Toolkit and app templates, and any consumer of the semantic brushes under
Cupertino would silently change. The shared ladder (Hover 0.08, Focused 0.12, Pressed 0.12, Dragged 0.16,
Selected 0.08, Medium 0.64, Low 0.32, Disabled 0.12) stands unchanged.

Apple's content dimming is expressed as **control-level** keys, declared with the control that uses them
(inside `ThemeDictionaries` so they can be overridden):

| Key | Value | Use |
|---|---|---|
| `CupertinoPlainButtonPressedOpacity` | 0.75 | plain / text buttons |
| `CupertinoGrayButtonPressedOpacity` | 0.60 | gray / bordered buttons, segments |
| `CupertinoIconButtonPressedOpacity` | 0.40 | bar buttons, hyperlink, icon buttons |
| `CupertinoSelectionPressedOpacity` | 0.70 | checkbox, radio |
| `CupertinoControlDisabledOpacity` | 0.50 | button, switch, slider, checkbox, radio, progress |
| `CupertinoTextDisabledOpacity` | 0.30 | tertiaryLabel-class dimming |

## 2. Cupertino-only colour keys (additive, `Cupertino*`)

All existing public keys are kept (resource keys are public API, AGENTS.md §6). Values move to the June-2025
palette — a value change, documented, not a key change.

| Family | Keys | Notes |
|---|---|---|
| System colours | `Cupertino{Red,Orange,Yellow,Green,Mint,Teal,Cyan,Blue,Indigo,Purple,Pink,Brown}Color` + `Brush` | Mint / Cyan / Brown are new; the existing nine keep their names |
| Grays | `Cupertino{Primary,Secondary,Tertiary,Quaternary,Quinary,Senary}GrayColor` + `Brush` | existing names; no duplicate `Gray1..6` spelling (YAGNI) |
| Labels | `LabelColor`, `SecondaryLabelColor`, `TertiaryLabelColor`, `QuaternaryLabelColor`, `PlaceholderTextColor` (+ `Cupertino*Brush`) | unchanged keys; **alpha values** as Apple publishes them — these are the translucent variants for use over arbitrary backdrops |
| Fills | `SystemFillColor`, `Secondary/Tertiary/QuaternarySystemFillColor` (+ brushes) | unchanged keys; alpha |
| Backgrounds | `SystemBackgroundColor`, `Secondary/Tertiary…`, `SystemGroupedBackgroundColor`, `Secondary/Tertiary…` (+ brushes) | unchanged keys |
| Separators / link | `SeparatorColor` (alpha), `OpaqueSeparatorColor`, `LinkColor` (+ brushes) | `LinkColor` tracks Blue |
| Glass tints (new) | `CupertinoGlassTintColor` (`#8CF2F2F5` / `#8CFAFAFC`), `CupertinoGlassProminentTintColor` (= accent), `CupertinoBarTintColor` (`#C2FFFFFF` / `#C21A1A1C`), `CupertinoPopoverTintColor` (`#C2FAFAFC` / `#C22C2C2E`), `CupertinoSheetTintColor` (`#E6F6F6F8` / `#E61C1C1E`), `CupertinoDialogTintColor` (`#C9FAFAFC` / `#D11C1C1E`), `CupertinoDimmingColor` (`#59000000`) | `Color` resources fed to `GlassPanel.TintColor`; alpha = tint strength **[measure]** |
| Switch | `CupertinoSwitchOnColor` (= Green), `CupertinoSwitchOffColor` (`#E9E9EB` / `#39393D`), `CupertinoKnobColor` (`#FFFFFF`) | |

**Where the `Cupertino*Brush` keys live and how they follow overrides and seeds.** They are declared in
`Styles/Application/CupertinoBrushes.xaml` — merged by `BaseDictionaries.xaml` (so they are part of the
theme's Source bundle, not the colour layer) — as `SolidColorBrush Color="{StaticResource …Color}"`. A
`StaticResource` snapshots at parse time, so on every rebuild `CupertinoTheme.AddThemeSpecificResources`
rewrites their `Color` from the resolved colour layers through the same mechanism `SemanticBrushUpdater`
uses for the shared brushes (`Apply` generalised to take a key list; `CupertinoConstants.BrushColorKeys`
maps brush key → colour key). That gives legacy brushes live override and seed support, and keeps the
brush *instances* stable for consumers holding `{ThemeResource}` references.

Light / Dark key-set and type parity is enforced by a runtime test that iterates
`CupertinoConstants.PaletteKeys` and reads each theme block through `ThemeDictionaries.TryGetValue("Light" / "Default")`
(a XAML-backed dictionary cannot be enumerated on Uno; the key list is the source of truth, per AGENTS.md §9).

No `HighContrast` block (D-8 cut): WinUI `HighContrast` is the OS high-contrast mode and is never selected
on Skia heads; Apple's "Increase Contrast" would be a `CupertinoTheme.IncreaseContrast` switch beside
`ReduceTransparency` if ever requested.

### Font family (D-3)

- `DefaultFontFamily` = **Inter** (`Uno.Fonts.Inter`, already a repo dependency for Simple), declared in
  `Fonts.xaml` for `Light` / `Default` / `HighContrast`. SF Pro cannot be shipped (license, see
  `apple-hig-reference.md` §3.4) and cannot be relied on by name on non-Apple Skia hosts. Hidden costs,
  accepted: Inter is not metric-compatible with SF (17 / 15 / 13 read slightly larger), and every
  Cupertino app ships ~1 MB of Inter even on iOS where SF exists.
- `CupertinoFontFamily` stays as an alias of `DefaultFontFamily` and is listed in
  `CupertinoTheme.FontFamilyAliasKeys`, with every per-control `Cupertino*FontFamily` alias the styles
  declare, so a runtime `DefaultFontFamily` change reaches the templates (lesson in `specs/lessons.md`).
  **Overriding `CupertinoFontFamily` reaches nothing** (it is a dead alias, same lesson); the docs and the
  legacy `CupertinoFonts` shim translate a `CupertinoFontFamily` override into `DefaultFontFamily` (§8).
- Apple-host consumers opt into the system font with one line:
  `<CupertinoTheme DefaultFontFamily=".AppleSystemUIFont" />` — measured on macOS
  (`liquid-glass-rendering.md` §10); iOS unverified. `SF Pro` / `SF Pro Text` / `system-ui` do **not**
  resolve through Skia, even on a Mac.

## 5. Motion tokens

Declared in `AnimationConstants.xaml` **inside `ThemeDictionaries`** (Light / Default / HighContrast, same
value in each) — a top-level key in the merge glob is one of mergedpages' own resources and no generated
layer could shadow it (lesson). Every Cupertino storyboard reads its `Duration` through one of these keys.

`CupertinoTheme.ReduceMotion=true` writes zero for every key below through `AddThemeSpecificResources`.
This is **construction-time**, like `DefaultCornerRadius`: a `Storyboard`'s `Duration` resolves when the
template is applied, so the flag affects controls created afterwards (or after a theme-change pass /
root recreation). `GlassPanel` additionally reads `CupertinoReduceMotion` when it loads and skips its
press animation. The test asserts a realized control's animation `Duration`, not `TryGetValue`.

| Key | Value | Use |
|---|---|---|
| `CupertinoPressDuration` | 0:0:0.13 | press scale / opacity |
| `CupertinoStateDuration` | 0:0:0.18 | hover / selection fills |
| `CupertinoSwitchDuration` | 0:0:0.33 | knob travel |
| `CupertinoPopoverDuration` | 0:0:0.18 | menu / popover open (scale 0.94 → 1, opacity 0 → 1) |
| `CupertinoMorphDuration` | 0:0:0.35 | glass press / release spring-back |
| `CupertinoAnimationDuration` (legacy) | 0:0:0.10 | kept, literal |
| `CupertinoTextBoxAnimationDuration` (legacy) | 0:0:0.25 | kept, literal |
| `CupertinoEaseOutFunction` / `CupertinoEaseInOutFunction` (legacy) | CubicEase | kept |

declared there too. Cupertino-only variants carry `Cupertino*` names. Legacy style keys remain as aliases
(§8). Glass appears only where Apple puts it — bars, floating controls, popovers, dialogs and the opt-in
glass button styles — and never in item templates.

## 8. Legacy compatibility surface and breaking changes

| Legacy API | Disposition |
|---|---|
| `CupertinoResources` (+ `WithImplicitStyles`) | Kept, `[Obsolete("Use CupertinoTheme")]`, and **is** the theme: `CupertinoResources : CupertinoTheme`. Its ctor reads the static override URIs recorded by `CupertinoColors.OverrideSource` / `CupertinoFonts.OverrideSource` (the existing "delay-one" hack — URIs, never instances, so the WinAppSDK two-parents rule is not hit) and passes them to the base as colour / font overrides. Being the theme itself, it sits at the top level of `MergedDictionaries`, so `Application.GetTheme()` finds it and nothing is parsed twice. `WithImplicitStyles` becomes a no-op and **implicit styles are now always on** (behaviour change for consumers that never set it; documented) |
| `CupertinoColors` | Kept, `[Obsolete]`; records the override URI only — it no longer merges the palette (the theme does). A consumer that declared it *after* `CupertinoResources` gets no override, exactly as today |
| `CupertinoFonts` | Kept, `[Obsolete]`; records the override URI. A legacy override file that redefines `CupertinoFontFamily` is **translated** into a `DefaultFontFamily` override when the theme resolves it (otherwise it would be a dead alias) |
| `CupertinoConstants` | Gains `ResourcePaths`, `SemanticStyleKeys`, `PaletteKeys`, `BrushColorKeys` (test and rewrite inputs; AGENTS.md §9) |
| All `Cupertino*Style` keys in `doc/cupertino-controls-styles.md` | Kept as aliases to the new styles (§6). **Visual change**: e.g. `CupertinoContainedButtonStyle` becomes a glass capsule |
| All `Cupertino*Color` / `Cupertino*Brush` / label / fill / background keys | Kept; **values updated** to the June-2025 palette |
| `CupertinoDisableStateOpacity` 0.5, `CupertinoMediumOpacity` 0.74, `CupertinoHoverOpacity` 0.85, `CupertinoHoverOverlayOpacity` 0.15, `CupertinoLowOpacity` 0.38, `CupertinoFocusedOpacity` 0.12, `CupertinoPressedOpacity` 0.40, `CupertinoPressedOverlayOpacity` 0.60, `CupertinoDraggedOpacity` 0.08, `CupertinoSelectedOpacity` 0.08 | Kept as **literal values** — they are content opacities and must never alias the shared overlay ladder |
| `CupertinoButtonPadding` (20), `CupertinoButtonCornerRadius` (8), `CupertinoButtonFontSize` (14) | Kept; **values change** to 16,7 / `RadiusFull` / 17 |
| `CupertinoDeterminateAnimation_Uno`, `CupertinoIndeterminateAnimation_Uno` | **Removed** with the Lottie dependency (D-7). Consumer action: if your app used `AnimatedVisualPlayer` through Cupertino's transitive reference, add `Lottie` to your own `UnoFeatures` |
| Transitive `Uno.WinUI.Lottie` reference | **Removed** (same) |
| `Uno.Toolkit` `CupertinoToolkitTheme` | Key-compatible; Phase 1 inventories every Cupertino key it reads before closing; follow-up to derive it from `CupertinoTheme` like `MaterialToolkitTheme` |

All of the above ships in the next **major** version; a frozen, opt-in `CupertinoResourcesV1`
(today's dictionaries merged into `Generated/mergedpages.v1.xaml`, no tests, removed in the following
major) gives pinned consumers an escape hatch (D-1).
